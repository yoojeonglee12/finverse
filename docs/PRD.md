## 2. 제품 정의

### 2.1 문제

금융소비자는 예측 가능한 비합리성(과신·손실회피·FOMO·현재편향·기준점 의존)으로 목표에 맞지 않는 결정을 반복한다. 기존 서비스(뉴스·증권앱·금융교육·모의투자)는 **정보는 주지만 판단을 훈련시키지 못한다.**

### 2.2 해결

**사용자가 던진 질문에 대해, 지금 시장 상황을 온톨로지로 구조화하고 에이전트 시뮬레이션으로 조건부 미래 시나리오를 만들어, 그 시나리오 앞에서 자기 판단을 시험하게 한다.**

파는 것은 **예측값이 아니라 조건**이다. "KOSPI가 7,500 간다"가 아니라 **"외국인 수급이 3거래일 이상 돌아오고, 실적이 컨센서스를 10% 이상 웃돌고, AI CapEx가 유지될 때에만"** 그 경로가 열린다고 말한다.

### 2.3 핵심 흐름

```
사용자 질문
  → 질문에 맞는 검색 범위 결정
  → 시장·경제·외부 사건·심리 정보 수집
  → 현재 시장 상황 온톨로지 구성
  → MiroFish 시뮬레이션
  → 사용자 질문에 맞는 미래 시나리오
```

### 2.4 두 개의 화면

| 탭 | 역할 | 성격 |
| --- | --- | --- |
| **시장 인사이트** | 오늘 시장이 왜 움직였는지 + 시나리오 목록·상세 | 정보제공 |
| **마이 금융 트윈** | 그 시나리오가 **내 자산**에 미치는 경로 + 대가 관점 + 편향 체크 | **상호작용** |

**시나리오는 두 탭을 잇는 유일한 객체다.** 시장 인사이트에서 만들어지고, 금융 트윈에서 내 자산에 적용된다.

## 4. 시스템 아키텍처 — 6단계 파이프라인

【구현됨 — UI】 `app/page.tsx`의 `ScenarioBuildScreen`에 6단계가 진행 상태로 구현되어 있다. **엔드포인트는 화면에 표기만 되어 있고 백엔드는 아직 없다.**

| # | 단계 | 엔드포인트 | 하는 일 | 산출 |
| --- | --- | --- | --- | --- |
| 01 | **Ontology Generation** | `POST /api/graph/ontology/generate` | 환경 시드 + 사용자 프롬프트에서 **엔터티 타입·관계 타입**을 구성 | 엔터티 7종 · 관계 6종 |
| 02 | **GraphRAG Build** | `POST /api/graph/build` | 온톨로지를 실제 데이터로 채워 그래프로 묶음 | **42 노드 · 68 엣지 · 7 스키마** |
| 03 | **Generate Agent Profiles** | `POST /api/simulation/prepare` | 엔터티를 역할별 에이전트로 변환 (관점·활동량·편향 설정) | **에이전트 24명** |
| 04 | **Generate Config** | `POST /api/simulation/prepare` | 라운드 수·활동 시간대 가중치·모델 설정 계산 | 시뮬 설정값 |
| 05 | **Initial Activation Orchestration** | `POST /api/simulation/prepare` | 첫 행동·내러티브 방향·핫토픽 고정 | 시작점 |
| 06 | **Scenario Simulation** | `POST /api/simulation/start` | MiroFish 시뮬 실행 → 시나리오 합성 | `Scenario` |

**활동 시간대 가중치** 【구현됨】 — 에이전트 활동량을 시간대로 조절한다.

| 시간대 | 배수 |
| --- | --- |
| Peak 19:00–22:00 | ×1.5 |
| Work 09:00–18:00 | ×0.7 |
| Morning 06:00–08:00 | ×0.4 |
| Off-Peak 00:00–05:00 | ×0.05 |

### 4.1 입력 — 시나리오 시드

시뮬은 세 가지 입력을 받는다 【구현됨 — 빌더 모달】:

1. **사용자 프롬프트** — 예: *"8월 말까지 외국인 수급과 반도체 실적이 KOSPI에 미치는 영향을 비교해줘."*
2. **환경 시드** — 선택형 조건. 예: `외국인 순매수 회복`, `SK하이닉스 실적 서프라이즈`
3. **기간** — 예: 30일
4. **파일 업로드** 【구현됨 — UI만】 — 사용자가 자기 자료를 시드로 추가

### 4.2 안전 불변식

- **조건부로만 말한다** — 단일 수치 단정 금지. 시나리오는 항상 `조건 → 경로 → 반증 신호` 3종 세트를 갖는다.
- **밴드 표기** — 중심값과 함께 밴드를 제시한다. 예: *1개월 중심값 7,500 · 밴드 6,700~8,300*
- **반증 신호 필수** — 모든 시나리오는 "이 시나리오를 취소해야 하는 신호"를 명시한다.
- **실계좌 연동 없음** — 트윈은 가상 프로필. 화면에 *"실제 계좌와 다를 수 있습니다"* 상시 표기.
- **상품 추천 금지** · **대가 페르소나 면책 라벨 상시**.
- **커뮤니티는 사실이 아니라 심리 관측값** — 언급량과 시장 방향을 동일 취급하지 않는다.

## 5. 도메인 모델 — 네 가지 정보 영역

【기준 문서: [온톨로지](./ontology/finverse-ontology.md)】

| 영역 | 답하는 질문 | 담는 것 |
| --- | --- | --- |
| **시장** | 실제로 무엇이 움직였나 | 지수·섹터·종목 · 시가/고가/저가/종가/거래량 · 외국인·기관 수급 · 변동률/변동성 · **최소 1년 히스토리** |
| **경제** | 어떤 환경에 놓였나 | 환율 · 기준금리 · 단기/5년/10년 국채 · 물가 · 고용 · 경기지표 · **예상값과 실제값의 차이** |
| **외부 사건** | 무슨 일이 원인이었나 | 뉴스 · 기업 실적/전망 · CapEx · 정책/규제 · 무역분쟁 · 지정학 · 공급망 |
| **사람들의 심리** | 사람들은 어떻게 반응하나 | 언급량 · 긍정/부정 · 공포/낙관 · FOMO · 군집행동 · **심리 변화 속도** |

### 5.1 영역 간 관계

```
외부 사건 → 경제        경제 → 시장          시장 → 사람들의 심리
외부 사건 → 시장        사람들의 심리 → 시장  과거 유사 사례 → 현재 상황 해석
```

**심리는 시장의 결과이자 원인이다** — 유일하게 양방향인 관계다.

### 5.2 그래프 스키마 【구현됨 — 타입만】

| 구분 | 값 |
| --- | --- |
| **엔터티 타입 7종** | 지수 · 종목 · 섹터 · 이벤트 · 환율 · 수급 · 금리 |
| **관계 타입 6종** | `DRIVES` · `IMPACTS` · `TRACKS` · `CORRELATES_WITH` · `CONSTRAINS` · `TRIGGERS` |
| **규모(예시 실측)** | 42 노드 · 68 엣지 |

> 【미확정】 **관계 타입 6종의 의미가 아직 정의되지 않았다.** 특히 `DRIVES` / `IMPACTS` / `CONSTRAINS`의 경계가 불분명하고, 방향·부호·강도를 어디에 담을지 정해지지 않았다. → §11 오픈 이슈 1

### 5.3 히스토리컬 데이터 원칙

- 가격은 **일 단위 OHLCV**, 수집 기간 **최소 1년**(길수록 좋음), 시장 변화는 **주 단위로도** 정리.
- 큰 움직임(급등·급락·추세 전환)이 나온 시점의 뉴스·정책·경제 변화·수급·심리를 찾아 **원인을 분석**한다.
- 과거 이벤트의 **영향 방향·강도·지속기간**을 기록하고, 현재와 유사하면 시나리오 근거로 인용한다.
- ⚠️ **과거 결과를 미래의 정답으로 쓰지 않는다.** 현재 조건과의 차이를 반드시 함께 표시한다.

### 5.4 검색 원칙

```
사용자가 지정한 정보     → 반드시 검색
분석에 필요한 누락 정보  → LLM이 판단해 추가 검색
영향이 작거나 근거 부족  → 중립 처리
```

검색 결과는 **출처 · 수집 시각 · 관련 대상 · 영향 방향**과 함께 저장한다.

### 5.5 에이전트 구성 【구현됨 — 프로필 4종 예시】

에이전트는 **엔터티에서 파생**된다(단계 03). 각자 `type`(역할) · `stance`(성향) · 활동량 · 편향을 갖는다.

| 에이전트 | type | stance | 관점 |
| --- | --- | --- | --- |
| 외국인 수급 | Flow Analyst | SUPPORTIVE | 글로벌 자금 흐름 · 원/달러 |
| 반도체 실적 | Earnings Analyst | BULLISH | 실적 · HBM 수요 · 메모리 가격 |
| 거시경제 | Macro Agent | NEUTRAL | 미 금리 · 중국 경기 · 위험 프리미엄 |
| 시장 심리 | Sentiment Agent | CAUTIOUS | 뉴스 방향성 · 과매도 반등 판별 |

**시나리오 결과에는 3인의 해석이 노출된다** — `뉴스 수집가` · `애널리스트` · `퀀트 트레이더`. 시나리오 성격에 따라 **가중치가 다르다**:

| 시나리오 성격 | 가중치 |
| --- | --- |
| 수급형 (외국인 매도·환율) | 뉴스 40% · 애널리스트 20% · 퀀트 40% |
| 실적형 (반도체 실적 미스) | 뉴스 20% · 애널리스트 55% · 퀀트 25% |

> 【미확정】 24명의 에이전트가 어떻게 **3인의 해석으로 집계**되는지, 가중치를 누가 정하는지가 정의되지 않았다. → §11 오픈 이슈 2

### 6.4 Scenario — 최종 산출물 【구현됨 — 타입 확정】

```ts
type Scenario = {
  id: string; title: string; duration: string; tags: string[];
  forecast: string;                    // "+24.5%" 등 요약 표기
  tone: "up" | "down";                 // 빨강=상승 / 파랑=하락
  image: string;
  summary: string; thesis: string; context: string;
  chapters:      { title: string; body: string; evidence: string }[];   // 4장 내러티브
  investorGuide: { stance: string; action: string; rationale: string }[];
  studyGuide:    { topic: string; question: string }[];
  biasChecks:    { bias: string; trap: string; counter: string }[];
  path: number[];                      // 예측 경로 (차트)
  events:        { week: string; category: string; title: string; body: string; impact: string }[];
  agentInsights: { role: string; title: string; body: string }[];       // 뉴스/애널리스트/퀀트
  riskPoints: string[];
};
```

**`biasChecks`가 이 제품의 정체성이다.** 시나리오마다 편향 3종을 `함정(trap)` + `대응(counter)` 쌍으로 제시한다. 현재 구현된 편향 목록:

`FOMO` · `확증 편향` · `기준점 편향` · `손실 회피` · `평균단가 집착` · `낙관적 과신` · `처분 효과` · `군집 행동` · `통제 착각`

### 6.5 UserTwin 【구현됨 — 목데이터】

```jsonc
  "holdings": [ { "name","code","value","weight","change","contribution" } ],
  "netWorthSeries": [ /* 최근 6개월 */ ] }
```

> 【미확정】 트윈 입력을 **사용자가 어떻게 채우는지** 화면이 없다. 지금은 하드코딩된 목데이터다. → §11 오픈 이슈 3

## 9. 비기능 요구사항

### 9.1 ⚠️ 최대 리스크 — 캐시가 성립하지 않는다

**질문마다 온톨로지를 새로 만들면 캐시 키가 없다.** 사용자가 프롬프트를 한 글자만 바꿔도 전체 6단계가 다시 돈다.

| | 규모 |
| --- | --- |
| 그래프 | 42 노드 · 68 엣지 |
| 에이전트 | **24명** |
| 라운드 | **24** |
| 발언 시도 | 24명 × 24라운드 × 시간대 가중 ≈ **수백 회 LLM 호출** |

→ **질문 1건당 비용이 시뮬 1회 전체다.** 유저가 늘면 선형으로 증가한다.

**완화 후보** 【미확정 — §11 오픈 이슈 4】

1. **레이어 분리 캐시** — 단계 01~02(온톨로지·그래프)는 질문과 무관한 부분이 크다. **시장 전체 그래프를 매일 1회 미리 빌드**해 두고, 질문별로는 서브그래프만 잘라 쓴다. → 01·02 비용이 질문 수와 무관해진다.
2. **시드 조합 캐시** — 프롬프트 원문 대신 **정규화된 시드 조합 + 기간**을 캐시 키로. 표현이 달라도 같은 조건이면 재사용.
3. **사전 생성 시나리오** — 대표 시나리오 3~5개는 배치로 미리 만들어 두고(현재 하드코딩된 3개가 그 역할), 사용자 생성은 그 위에 얹는다.
4. **비동기 잡 큐** — 요청 핸들러에서 시뮬을 돌리지 않는다. 잡 등록 → 진행 폴링(6단계 UI가 이미 그 모양) → 완료 시 서빙.

> **최소한 4번(비동기 잡 큐)은 필수다.** 6단계 진행 화면이 이미 그 전제로 만들어져 있다.

### 9.2 성능·비용 지침

- **프롬프트 캐싱** — 그래프 스냅샷·에이전트 프로필처럼 시뮬 내내 고정인 콘텐츠를 프리픽스 앞에 둔다. system에 시각·UUID·질문 id 금지(프리픽스 오염).
- ⚠️ 에이전트를 **동시에 한꺼번에 던지면 전원 캐시 미스**. 1개 먼저 보내고 첫 토큰 수신 후 팬아웃.
- **effort가 1차 비용 레버** — 모델 교체보다 먼저 시도. 에이전트 발언처럼 정형화된 작업은 낮은 effort로 스윕.
- **Batch API** — 사전 생성 시나리오·히스토리컬 원인 분석 등 지연 무관 경로는 50% 절감.
- **구조화 출력** — `Scenario` 스키마를 json_schema로 강제. 문자열 파싱 금지.
- **결정론적 계산은 LLM 밖으로** — 트윈 자산 경로는 `시나리오 경로 × 보유 비중` 곱셈이다.
- **상한과 폴백** — 잡별 토큰 상한·타임아웃·재시도 상한. 실패 시 사전 생성 시나리오로 폴백(빈 화면 금지).

### 9.3 엔진 제약 (MiroFish)

OASIS + Zep Cloud 기반, **AGPL-3.0**. 단일프로세스·무인증·비재현(난수 시드 없음)·토큰 폭식. [코드해부 리포트](./MiroFish-코드해부-리포트.html) 참조.

- **재현성 없음** — 같은 입력이 같은 시나리오를 만들지 않는다. 사용자에게 "같은 질문 = 같은 답"을 약속할 수 없다. 시드 고정이 가능한지 확인 필요.
- **AGPL §13** — 사용자 요청이 트리거하는 네트워크 서비스는 §13 대상이 될 수 있다. 완화 설계는 **생성기를 별도 프로세스로 두고 스냅샷 JSON 단방향 통신**. 법률 판단은 별건. → §11 오픈 이슈 6

## 부록 A. 용어집

- **온톨로지**: 질문에 맞춰 구성한 엔터티 타입 + 관계 타입의 집합 (단계 01 산출)
- **그래프 / GraphRAG**: 온톨로지를 실제 데이터로 채운 것 (단계 02 산출)
- **환경 시드**: 시나리오 생성의 전제 조건. 사용자가 선택하거나 파일로 올린다
- **에이전트 프로필**: 엔터티에서 파생된 시뮬 참여자. 역할·성향·활동량·편향을 가짐
- **Scenario**: 최종 산출물(§6.4). 내러티브 + 경로 + 편향 체크 + 에이전트 해석 + 리스크
- **반증 신호**: 시나리오를 취소해야 하는 조건. 모든 시나리오에 필수
- **기여도(contribution)**: 개별 종목이 지수 변동에 기여한 %p
