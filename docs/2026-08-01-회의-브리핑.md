# 8/1 회의 브리핑 — 개발팀 설명용

> **작성** 이유정(기획) · **대상** 임영진·장진우·신민수(개발), 곽동규(세계관) · **작성일** 2026-07-31
> **목적** ① 우리가 뭘 만드는지 한 번에 공유 ② 개발 착수를 막고 있는 결정 4건을 오늘 끝내기

**읽는 법** — 시간 없으면 **§1 + §7**만. 구현 담당이면 **§3~§6**. 회의 진행은 **§7**.

---

## 1. 한 장 요약

**만드는 것**: 매일 갱신되는 시장 세계관 위에서, 오늘의 뉴스 사건이 **내 포트폴리오에 닿는 경로**를 보여주고, 그 앞에서 사용자가 자기 판단을 시험해 **인지 편향을 발견**하게 하는 서비스.

**안 만드는 것**: 가격 예측, 종목 추천, 실계좌 연동. (전부 안전 원칙상 금지)

**한 문장 구조**:
> 매크로 지표가 **섹터**를 흔들고, 내가 가진 종목은 **섹터에 속해** 있으므로, 사건 → 내 자산 영향은 **2-hop 곱셈**으로 계산된다.

이 한 문장이 전체 설계를 결정한다. 그래프 엣지도, 관계DB도, 시뮬 규모도, 화면도 전부 여기서 나온다.

**세 화면은 나란한 기능이 아니라 같은 세계관을 좁혀 쓰는 3단계**:

| | 화면 | 보는 범위 | 성격 |
| --- | --- | --- | --- |
| **C** | V1 시장 인사이트 | 세계 전체 | 정보제공 |
| **B** | V2 이벤트 시뮬 | 사건 하나로 흔든 세계 | 정보제공 |
| **A** | V3 나 트윈 **(핵심)** | 내 것만 하이라이트한 세계 | **상호작용** |

흐름 **C → B → A**, 비중 **A > C > B**.

## 2. 서비스 시나리오 — 사용자 3분

> 실제 화면 흐름 그대로. 각 단계 옆 괄호는 **어느 데이터가 소비되는지**.

**[0] 최초 1회 · 트윈 설정** — 투자 성향, 가용 자금, 목표(예: 3년 내 5천만), 보유/관심 종목을 입력한다. 보유 종목이 없으면 템플릿 포트폴리오를 고른다. → `UserTwin` 저장(L2, 비공개)

**[1] 아침에 접속 · V1 시장 인사이트 (C)** — 오늘의 세계관 그래프가 떠 있다. 지표 10개의 오늘 값, 섹터 9개의 등락, 그리고 **일간 인사이트 리포트** 한 단락. 리포트 문장에는 관계 id가 근거로 달려 있다("미국채 10년물 상승이 2차전지에 부담 — R-014"). 아래에 **오늘의 이벤트 카드 3~5장**. → `BaseModel`

**[2] 카드를 누른다 · V2 이벤트 시뮬 (B)** — "FOMC 금리 동결". 처음 눌린 카드면 생성이 돌고(수십 초), 이미 누군가 눌렀으면 **즉시 캐시에서** 뜬다. 화면에는 매크로 에이전트(연준·한은…)와 섹터 에이전트 9개가 라운드로 주고받은 **타임라인**, 각 발언이 활성화한 관계 엣지, 그리고 결과물인 **섹터별 충격 팩터**와 30일 **3경로 범위**. → `EventSimulation` (캐시 키 = 카드 id + BaseModel 날짜)

**[3] "나한테는?" · V3 나 트윈 (A)** — 같은 사건, 그러나 화면은 **내 종목 → 소속 섹터 → 연결 매크로**만 선명하고 나머지는 흐리다. 섹터 충격 팩터 × 내 보유 비중 = **내 포트폴리오 영향**이 곱셈식 그대로 노출된다(LLM 아님, 검산 가능).

**[4] 판단한다** — 대가 4인의 관점을 참고로 볼 수 있다(버핏은 관망, 캐시 우드는 매수…). 참고만 하고 **내 선택**을 고른다: 유지 / 일부 실현 / 추가 매수. 그리고 **"왜 그렇게 판단했나"** 한 줄을 쓴다.

**[5] 피드백** — 목표 달성 확률이 before → after로 바뀐 걸 보여주고, 내 선택과 이유에서 **편향 신호**를 판정한다. 편향이 없으면 "편향 신호 없음"이라고 정직하게 말한다. 반복하면 나의 **아키타입**(가치/매크로/성장/사이클)이 쌓인다. → `PersonalizationResult`, `biasHistory`

**핵심 전환점은 [2]→[3]**. 관찰자에서 당사자가 되는 순간이고, 이 서비스가 뉴스앱과 갈라지는 지점이다. 성공지표도 **B→A 전환률**이 북극성에 가장 가깝다.

## 3. 설계 — 4층과 갱신 주기

```
⓪ 외부 데이터 연동 ────── 매일 1회 ──── 지표 시세 · 경제 캘린더 · 뉴스 피드
        │
① BASE MODEL ─────────── 매일 1회 재구성 ── 읽기전용 세계관 (모든 화면의 공통 기반)
        │   └ 관계DB 참조 ── 분기 갱신 ── 방향·부호·강도·근거
        │
② 이벤트 시뮬 ────────── 카드당 1회 생성 후 캐시 ── 매크로 agent × 섹터 agent
        │
③ 나 트윈 ─────────────── 유저 요청 시 ── 결정론적 곱셈 + LLM ≤2회
```

**층별로 절대 넘지 말 것** (이게 무너지면 비용과 무결성이 동시에 깨진다):

| 층 | 넘지 말 것 |
| --- | --- |
| ⓪ | 관계(인과 구조)를 건드리지 않는다. state만 갱신 |
| ① | 유저별로 달라지지 않는다 (읽기전용 L1) |
| ② | 유저별로 재실행하지 않는다 (캐시 키로 공유) |
| ③ | 무거운 시뮬 재실행 금지 (곱셈 + LLM ≤2회) |

**왜 state와 관계의 주기를 나눴나** — 인과 구조가 매일 흔들리면 Base Model이 "안정적 기반"이 아니게 된다. 지표 **값**은 매일 변해도, "금리가 오르면 2차전지에 부담"이라는 **구조**는 분기 단위로만 손댄다.

**무결성 (L1/L2)**: Base Model·시뮬 캐시는 읽기전용(L1), 유저 기록은 트윈(L2)에만. **유저가 쓸 수 있는 공유 그래프를 만들지 않는다.**

## 4. 도메인 모델 — 왜 종목이 아니라 섹터인가

| 계층 | 개수 | 그래프 엣지 |
| --- | --- | --- |
| 매크로 (지표 10 · 기관 7 · 이벤트) | ~25 | ✅ 섹터와 연결 |
| **섹터 (MECE 9개)** | 9 | ✅ 매크로와 연결 |
| 종목 (KOSPI 100) | 100 | ❌ **섹터 멤버십만** |

> **엣지는 매크로 ↔ 섹터 사이에만 존재한다.** 종목은 매크로와 직접 연결하지 않는다.

**이 제약이 사주는 것 3가지**:
1. **엣지 수 축소** — 수백 → **73행**. 큐레이션이 가능한 규모가 된다.
2. **시뮬 규모 축소** — 에이전트가 종목 100개가 아니라 **섹터 9개**. 그래서 온디맨드 생성이 가능해졌다(결정 #18).
3. **자산 영향 계산이 2-hop 곱셈** — `섹터 충격 팩터 × 내 종목 비중`. LLM 불필요, 검산 가능.

**섹터 9개** (가르는 기준은 산업 분류가 아니라 **매크로 시그니처** — 어느 지표에 어떤 방향으로 반응하는가):

| # | 섹터 | 종목 | 1차 동인(강) |
| --- | --- | --- | --- |
| S1 | 반도체·IT하드웨어 | 10 | 반도체수요(+) · 외국인수급(+) |
| S2 | 인터넷·소프트웨어·콘텐츠 | 9 | 미10년물(−) |
| S3 | 2차전지·화학소재 | 8 | 전기차수요(+) · 미10년물(−) |
| S4 | 자동차·조선·방산 | 18 | 원/달러(+) |
| S5 | 금융 | 12 | 한국기준금리(+) |
| S6 | 헬스케어 | 7 | 미10년물(−) |
| S7 | 소비재·유통·통신 | 12 | CPI(−) |
| S8 | 에너지·소재 | 12 | 유가·환율 혼재 |
| S9 | 건설·인프라·운송 | 12 | 한국기준금리(−) |

**관계DB — 근거 없는 정밀 수치 금지**. 강도는 `약/중/강` 3단계 질적 값이 정직한 한계선이다. `0.73` 같은 숫자는 만들 근거가 없다.

```jsonc
{ "id":"R-014", "from":"us10y", "to":"sec-battery",
  "kind":"drives", "sign":-1, "strength":"strong", "lag":"short",
  "basis":"고성장·장기 현금흐름 섹터는 할인율 상승에 민감",
  "evidence":["공개 자료 URL"], "confidence":"mid", "reviewedAt":"2026-07-31" }
```

**어휘 5개 + 1 제안**: `sets`(기관→지표) · `transmits`(지표→지표) · `drives`(지표→섹터) · `triggers`(이벤트→지표/섹터) · `member_of`(종목→섹터) · **`regulates`【제안】**(기관→섹터)
**규모**: drives 47 + sets 6 + transmits 9 + triggers 8 + regulates 3 = **73행**

**등록 기준 — "이 관계를 지우면 뭐가 깨지나?"** 소비처는 3곳뿐이고, 어디에도 안 쓰이면 등록하지 않는다.
① 자산 영향 계산 ② 근거 인용(리포트·편향 카드) ③ 리플레이 연출

## 5. 데이터 계약 4개

개발은 이 4개만 맞으면 서로를 기다리지 않고 병렬로 갈 수 있다.

| 계약 | 생산자 | 소비자 | 주기 |
| --- | --- | --- | --- |
| `BaseModel` | 배치 파이프라인 | V1·V2·V3 전부 | 매일 1회 |
| `RelationDB` | 사람 큐레이션 | BaseModel 렌더 · 근거 인용 | 분기 |
| `EventSimulation` | 시뮬 생성기 | V2 표시 · V3 계산 입력 | 카드당 1회 (캐시) |
| `UserTwin` | 유저 입력 | V3 | 상시 (L2) |

**연결 조인트 3개** — 이것만 명세하면 A·B·C 연관관계는 닫힌다:
1. **V1의 이벤트 카드 클릭 → V2 생성** (카드 id = 시뮬 트리거이자 캐시 키)
2. **V2의 섹터 충격 팩터 → V3 계산 입력** (팩터 × 내 종목 비중)
3. **V3의 하이라이트 대상 = BaseModel의 부분집합** (내 종목 → 소속 섹터 → 연결 매크로)

상세 스키마는 **PRD §6**.

## 6. 모듈 4덩어리 & 분담 제안

```
[배치 파이프라인 · 매일]  외부연동 → state 갱신 → BaseModel 빌드 → 일간 리포트 → 카드 선별
        │  (관계DB 참조 · 분기 갱신)
[시뮬 생성기 · 카드당 1회]  경량 agent 시뮬 → EventSimulation 저장(캐시)
        │
[앱 서버 1개]  BaseModel 조회 · 카드 목록 · 시뮬 조회 · 트윈 저장 · 선택→피드백
        │
[화면 3개]  V1(C) · V2(B) · V3(A)
```

> **"매일 세계를 굽고, 카드마다 시뮬을 한 번 굽고, 서버 하나로 서빙하고, 화면 셋을 그린다."**

| 덩어리 | MVP | 담당(제안) |
| --- | --- | --- |
| 배치 파이프라인 (데이터 연동·그래프 빌드·리포트·카드 선별) | P0 | 개발 1 |
| 시뮬 생성기 (경량 agent · 캐시) | P0 | 개발 2 |
| 앱 서버 (조회 API 5개 · 트윈 · 편향 피드백) | P0 | 개발 3 |
| 관계DB 73행 큐레이션 | P0 | 기획 + 곽동규 |
| V1 / V2 / V3 화면 | P0 / P1 / P0 | 이유정 |

**임계 경로(MVP)**: 배치 파이프라인 + 관계DB → 앱 서버 → **V1 → V3**. V2는 P1로 뒤이어.
→ **V2가 늦어도 V1의 카드에서 V3로 직행하는 경로를 남긴다.** (V2는 차별화 요소지만 임계 경로는 아님)

**성능 설계 — 요청 경로에서 생성을 떼어낸다** (이거 하나가 나머지를 결정한다):
- 카드 클릭 → **잡 등록(즉시 응답)** → 진행 폴링/SSE → 완료 시 캐시에서 서빙. 요청 핸들러 안에서 시뮬 직접 실행 금지.
- 같은 카드 동시 최초 클릭 → **잡 1개만** 생성(싱글플라이트).
- 프롬프트 캐싱: BaseModel·관계DB는 하루 고정이므로 프리픽스에 고정 배치. **system에 시각·UUID·카드 id 금지**.
- ⚠️ 섹터 에이전트 9개를 **동시에 던지면 전원 캐시 미스**. 1개 먼저 → 첫 토큰 후 팬아웃.
- 부수 효과로 **AGPL 프로세스 분리**가 같이 해결된다(§7-C 참조).

상세 8항목은 **PRD §10.1**.

## 7. 8/1 안건

> **A그룹만 오늘 끝내면 개발이 출발한다.** B는 방향만, C는 담당·기한만 정하고 넘긴다.

### A그룹 — 개발 착수를 막고 있는 것 (오늘 결정 · 30분)

**A-1. 섹터 9개 안 승인** ⏱ 5분
- 결정 #15는 "7~8개"였는데 **9개로 늘렸다.** 8개 안에서는 S8 하나에 건설(금리−)·소재(금리+)·항공(환율−)·철강(환율+)이 섞여 **매크로 시그니처가 정면 충돌**했다. 섹터를 시그니처로 정의하는 이상, 시그니처가 상충하면 섹터가 아니다.
- **권장**: 9개 승인 + "#15의 7~8개를 9개로 조정" 사실을 회의록에 기록.
- ⚠️ 잔여 충돌 1건: **S-Oil**(정유, 유가+)이 S8(대체로 유가−)에 있다. **권장** — 멤버십에 `factorOverride`를 두어 종목 단위 예외 허용. (구조는 안 건드림)

**A-2. 관계DB 73행 검토** ⏱ 10분
- 전부 볼 시간은 없다. **강도(강/중/약)가 갈리는 행만** 보고, 나머지는 담당·기한만.
- 같이 결정: **`regulates` 어휘 추가 여부** (기관→섹터 직접, 예: 금융위→금융). 지표를 경유하지 않는 규제 작용을 표현할 수단이 지금 없다. **권장**: 추가(3행).
- **강도는 지금 근거가 약하다.** 실증 계획(초안 §6.1) 승인 필요 — 언제, 누가, 어떤 데이터로 검증할지.

**A-3. 이벤트 카드 선별 기준** ⏱ 10분
- 이게 없으면 배치 파이프라인의 마지막 단계를 못 짠다. 정할 것: **하루 몇 개**(비용 상한과 직결) · **무엇을 "매크로 관련"으로 볼 것인가** · 선별 자동/수동.
- **권장**: 하루 **3~5개** 상한 · 관계DB에 등록된 지표/기관/이벤트를 **언급한 뉴스**만 후보 · MVP는 **수동 선별**(자동화는 후속).

**A-4. 나 트윈 캐릭터 설정 항목 확정** ⏱ 5분
- V3가 P0인데 입력 스키마가 없으면 못 만든다. 항목: 투자 성향 · 가용 자금 · 목표(이름·기간·금액) · 보유/관심 종목.
- **무보유 유저**가 다수일 것이다. **권장**: 템플릿 포트폴리오 3종(안정형/균형형/성장형) 제공.

### B그룹 — 방향만 (오늘 10분)

**B-1. 대가 4인 엔터 수위 + 실명 사용 권리** — 재미와 면책의 균형. 실명 + 강한 면책 라벨 상시는 확정(결정 #5). 공모전 제출 조건에 실명 사용 제약이 있는지 **확인 필요**.

**B-2. 편향 판정에 "왜 그렇게 판단했나" 한 줄 입력** — **권장: 포함.** 선택지만으로는 편향을 못 가린다("일부 실현"이 손실회피일 수도 사이클 인식일 수도 있다). 이 입력이 LLM 2회 중 1회를 쓰는 곳이다.

### C그룹 — 담당·기한만 (오늘 5분, 결론은 다음 회의)

**C-1. 경량 시뮬 실측** — 결정 #18(온디맨드)의 **타당성 전제**다. 프로토타입 1회 돌려 **생성 시간·토큰** 실측 → SLO 확정. 이게 안 나오면 아키텍처를 되돌려야 할 수도 있다. **가장 중요한 숙제.**

**C-2. AGPL 의무 범위 법률 확인** — MiroFish가 AGPL-3.0인데, 결정 #18로 "유저 클릭이 트리거하는 경로"로 이동하면서 **§13(네트워크 조항)** 적용 여부가 달라졌다. §10.2의 프로세스 분리 설계(생성기 별도 프로세스 · 스냅샷 JSON 단방향 · 유저 요청 프록시 없음)가 트리거를 피하는지 **1회 검토**. 폴백: ① 생성기 소스 공개 ② 엔진 교체(계약 §6만 지키면 가능).

**C-3. 【신규】 간접 경로 전파 규칙** — 데모 만들다 발견한 미결 사항. `WTI → 소비재` 직접 엣지는 **없고** 실제 경로는 `WTI → CPI → 소비재`(2-hop)다. 같은 구조가 `미10년물 → 외국인수급 → 전 섹터`에도 있다.
- 질문: **간접 경로를 섹터 충격에 반영할 것인가?** 반영한다면 강도를 어떻게 합성하나(곱? 한 단계 감쇠?).
- **권장**: MVP는 **직접 엣지만** 반영하고, 화면에는 간접 경로를 **근거 문장으로만** 노출. 합성 규칙은 강도 실증(A-2) 이후.

### 이번 회의에서 다루지 않는 것

구조 변경으로 **소멸한 안건**: outcome 저장 방식(→ 팩터 × 비중 곱셈으로 계산, 사전 저장 불필요) · 전망 단일 수치 vs 범위(→ 범위 확정) · progressive disclosure 토글(→ V3 하이라이트에 흡수)
